# Peça 3 — Mostrar etapas e erros (fim/erro/SSE/ponte) na UI

## Objetivo

A interface deve mostrar claramente as etapas da conversa (transcrevendo, pensando, falando) e qualquer erro. O núcleo já emite eventos `fim` e `erro` via SSE/ponte (`src/conectores/ponte/cliente.ts:84`). Todo `erro`, queda do SSE ou falha da ponte deve virar estado de erro visível na UI — nunca deixar o usuário preso em "pensando" para sempre.

**Importante (atualização da frente 1 / PR #9):** o núcleo agora emite evento `erro` com `{erro: "cancelado"}` quando o pedido é cancelado pelo usuário. A interface deve tratar `"cancelado"` como **interrupção normal** (volta ao estado de repouso/idle), **não** como erro vermelho. Isso é diferente de um erro real de rede ou processamento.

## O que fazer

1. **Mapear os eventos existentes.** Leia `src/conectores/ponte/cliente.ts` para entender quais eventos chegam à interface (`inicio`, `texto`, `fim`, `erro`, etc.) e como eles são tratados hoje.

2. **Estados visuais.** Garanta que a UI tenha estados claros e mutuamente exclusivos:
   - `idle` / repouso: pronto para ouvir
   - `transcrevendo`: microfone ativo, texto chegando
   - `pensando`: aguardando resposta do núcleo
   - `falando`: reproduzindo áudio da resposta
   - `erro`: algo deu errado (com mensagem)

3. **Transições corretas.** Cada evento deve mover a UI para o estado certo:
   - Início de captura → `transcrevendo`
   - Fim de captura / início de espera → `pensando`
   - Primeira parte da resposta → `falando`
   - Evento `fim` → `idle`
   - Evento `erro` com `{erro: "cancelado"}` → `idle` (sem mensagem de erro)
   - Evento `erro` com qualquer outro valor → `erro` com mensagem descritiva
   - Queda do SSE / falha de conexão → `erro` com mensagem ("Conexão perdida", etc.)

4. **Nunca ficar preso.** Se a UI entrar em `pensando` ou `transcrevendo` e não receber nenhum evento por um tempo razoável, ou se o SSE cair sem evento `fim`, a UI deve sair desse estado (timeout ou detecção de desconexão).

5. **Testes.** Crie ou complemente testes em `tests/*.test.ts` cobrindo:
   - Transição para cada estado visual diante do evento correspondente
   - `erro: "cancelado"` volta ao idle sem mostrar erro
   - Erro real mostra mensagem de erro
   - Queda do SSE mostra erro de conexão
   - Nenhum cenário deixa a UI presa em estado intermediário
