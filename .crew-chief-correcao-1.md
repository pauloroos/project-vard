# Correção da peça 1 — handler config-salva (base: tentativa 4)

Você está continuando o trabalho da tentativa 4 desta peça. O worktree já contém a correção anterior; aplique **apenas** os ajustes abaixo sobre ela. Não refaça o que já funciona.

## Contexto

A tentativa 4 implementou `aplicarDispositivosSalvos` e um teste unitário. Uma revisão independente apontou três pendências reais que precisam ser resolvidas agora:

1. **Microfone aberto não troca nem avisa reinício.** `definirMicrofonePreferido` só vale para a próxima abertura. Quando o microfone já está aberto (`atual !== null` em `src/audio/microfone.ts`), trocar nas configurações não tem efeito imediato e o usuário não é avisado.
2. **Saída padrão ("") não é reaplicada no contexto vivo.** A condição `cfg.saida_id && ...` pula `setSinkId("")`, deixando a saída anterior ativa quando o usuário volta ao padrão do sistema.
3. **Teste cobre apenas o helper, não o handler real.** O teste importa e chama `aplicarDispositivosSalvos` diretamente, mas nunca dispara o evento Tauri `config-salva` nem exercita o listener registrado em `listen("config-salva", ...)` no `main.ts`.

## O que fazer

### 1. Microfone: avisar quando a troca não pode ser aplicada ao vivo

Em `aplicarDispositivosSalvos` (ou onde for mais natural no fluxo do handler):
- Após chamar `definirMicrofonePreferido(cfg.microfone_id)`, verifique se o microfone está atualmente aberto. Consulte `src/audio/microfone.ts` para encontrar como acessar esse estado (provavelmente uma variável de módulo ou função exportada).
- Se estiver aberto, chame `mostrarEstado("erro", "Reinicie para aplicar o microfone")` (ou equivalente visível) para avisar o usuário. Não force fechar/reabrir o microfone no handler (cortaria áudio no meio da conversa).
- Se não estiver aberto, nada adicional é necessário (a preferência será usada na próxima abertura).

### 2. Saída padrão: aplicar `setSinkId("")` no contexto vivo

Corrija a lógica em `aplicarDispositivosSalvos`:
- Quando `mudou.saida` for verdadeiro, chame `aplicarSaidaNoContexto(contexto)` **mesmo quando `cfg.saida_id` for vazio** (padrão do sistema).
- Em `src/audio/boca.ts`, ajuste `aplicarSaidaNoContexto` para não retornar prematuramente quando `!pref.saida_id`; permita que `setSinkId("")` seja chamado no contexto vivo.
- Se `setSinkId("")` falhar ou lançar exceção, trate como erro visível (igual às outras falhas de dispositivo).

### 3. Teste: disparar o handler `config-salva` real

Reescreva ou complemente `tests/config-salva-dispositivos.test.ts` para:
- Simular o evento Tauri `config-salva` usando o mesmo mecanismo dos testes existentes em `tests/retorno.test.ts` (consulte como eles mockam `@tauri-apps/api/event` e disparam eventos).
- Cobrir pelo menos estes cenários via handler real:
  - Troca de microfone com captura aberta → espera aviso de reinício.
  - Troca de microfone com captura fechada → define preferência sem aviso.
  - Troca de saída para dispositivo específico → aplica no contexto.
  - Troca de saída para padrão ("") → aplica `setSinkId("")` no contexto.
  - Falha de `setSinkId` → estado de erro visível.
- Cada teste deve **falhar na main atual** (antes da correção) e passar com ela. Rode `npm test -- tests/config-salva-dispositivos.test.ts` para confirmar.
