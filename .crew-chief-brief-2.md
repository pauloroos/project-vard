# Peça 2 — Interromper cancela transcrição, resposta e fala

## Objetivo

Quando o usuário interrompe (botão, atalho ou PTT), a interface deve cancelar imediatamente:
1. A transcrição em andamento (se houver captura ativa)
2. A requisição ao núcleo (SSE/ponte)
3. A reprodução de áudio da resposta (fila de frases e playback atual)

A interrupção deve ser limpa: sem vazamento de recursos, sem estados intermediários presos, sem áudio residual. O núcleo já emite `erro: "cancelado"` quando o pedido é cancelado; a interface deve tratar isso como interrupção normal (volta ao idle), não como erro.

## Contexto das peças relacionadas

- **Peça 3** (já aceita): implementou estados visuais incluindo `transcrevendo`, timeout de 30s para destravamento, e tratamento de `erro: "cancelado"` → `repouso` sem mensagem. Consulte `src/fala/conversa.ts` e `src/main.ts` para entender os estados e transições atuais.
- **Peça 4** (já aceita): implementou fila de reprodução frase-por-frase com `AbortController` e limpeza via `onAbort`. Consulte `src/fala/conversa.ts` para entender como a fila funciona e como `interromper()` já atua sobre ela.

**Importante:** leia o código atual antes de implementar. Parte do comportamento de interrupção pode já existir nas peças 3 e 4. Sua tarefa é garantir que a interrupção cubra **todos** os fluxos (transcrição, requisição SSE, fala) de forma integrada e testada.

## O que fazer

1. **Mapear o fluxo atual de interrupção.** Leia `src/main.ts`, `src/fala/conversa.ts`, `src/audio/microfone.ts` e `src/conectores/ponte/cliente.ts` para entender:
   - Como o botão/atalho/PTT dispara a interrupção hoje
   - O que já é cancelado (fila de fala? SSE? captura?)
   - O que falta cancelar

2. **Cancelar transcrição.** Se a captura de áudio estiver ativa (`estado === "transcrevendo"`), a interrupção deve:
   - Parar a captura de áudio (fechar o stream do microfone)
   - Descartar qualquer texto transcrito parcialmente
   - Transicionar para `repouso` (não `erro`)

3. **Cancelar requisição SSE/ponte.** Se uma requisição ao núcleo estiver em andamento (`estado === "pensando"` ou `falando` com SSE ativo):
   - Abortar a conexão SSE / fechar o canal da ponte
   - Descartar qualquer texto recebido parcialmente
   - Transicionar para `repouso`

4. **Cancelar fala.** Já parcialmente implementado na peça 4. Garanta que:
   - A fila de frases seja limpa (`fila.length = 0`)
   - O playback atual pare imediatamente (`boca.parar()`)
   - O `AbortController` seja sinalizado
   - Estado volte para `repouso`

5. **Integração com `erro: "cancelado"`.** Quando o núcleo responde com `erro: "cancelado"` após a interrupção, a interface deve:
   - Reconhecer como interrupção bem-sucedida
   - Voltar ao `repouso` sem mostrar mensagem de erro
   - Não iniciar nova captura automaticamente

6. **Testes.** Crie ou complemente testes em `tests/*.test.ts` cobrindo:
   - Interrupção durante `transcrevendo` → captura parada, estado → `repouso`
   - Interrupção durante `pensando` → SSE abortado, estado → `repouso`
   - Interrupção durante `falando` → fila limpa, playback parado, estado → `repouso`
   - `erro: "cancelado"` do núcleo → `repouso` sem mensagem de erro
   - Interrupção dupla (usuário clica duas vezes) → idempotente, sem crash
   - Recursos liberados após interrupção (sem listeners órfãos, timers pendentes)
