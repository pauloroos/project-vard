# Como trocar para o Vard 0.7 (app único)

Este documento descreve os passos para migrar da instalação legada (PowerShell + bandeja Python)
para o app único do Vard 0.7, onde o Rust assume o ciclo nativo e a bandeja é integrada.

## Pré-requisitos

- Windows 10/11
- Vard 0.6.x funcionando (instalação legada)
- Binário `vard.exe` da versão 0.7 disponível
- Nenhuma tarefa destacada ou reunião em andamento

## Passo a passo da migração

### 1. Parar a pilha antiga

```powershell
# Para serviços via interface de ciclo legada (não mate processos por nome)
.\scripts\windows\vard-modo.ps1 parar

# Confirme que não há PIDs residuais
Get-Process -Name vard,python,powershell -ErrorAction SilentlyContinue |
  Where-Object { $_.MainWindowTitle -match 'Vard|bandeja' }
```

### 2. Backup da configuração atual

```powershell
$dados = if ($env:VARD_DADOS) { $env:VARD_DADOS } else { "$env:LOCALAPPDATA\rdl-vard" }
Copy-Item "$dados\instalacao.json" "$dados\instalacao.json.bak-0.7"
Copy-Item "$dados\estado.json" "$dados\estado.json.bak-0.7" -ErrorAction SilentlyContinue
```

### 3. Habilitar o supervisor

Edite `%LOCALAPPDATA%\rdl-vard\instalacao.json` e defina `"supervisor": true`:

```json
{
  "supervisor": true,
  "servicos": {
    "voz": true,
    "reuniao": true,
    "openjarvis": true
  }
}
```

### 4. Atualizar atalhos

Execute o script de logon atualizado para recriar os atalhos apontando para `vard.exe`:

```powershell
.\scripts\windows\tarefa-logon.ps1
```

Com `supervisor: true`, os atalhos da pasta Startup e da área de trabalho passam a apontar
diretamente para `vard.exe`. O plugin de instância única garante que apenas uma cópia rode.

### 5. Iniciar o app novo

```powershell
Start-Process .\vard.exe
```

Ou clique no atalho `Vard` na pasta Startup / área de trabalho.

### 6. Verificar

- A bandeja nativa do Rust deve aparecer (ícone do Vard na bandeja do sistema)
- A bandeja Python **não** deve iniciar (log em `logs/bandeja.log` confirma)
- Os verbos via `vard-modo.ps1` devem publicar na caixa IPC (log em `logs/vard-modo.log`)
- `http://127.0.0.1:4710/saude` responde se a voz estiver configurada

## Rollback

Se algo falhar durante a migração:

### 1. Desabilitar o supervisor

```powershell
$dados = if ($env:VARD_DADOS) { $env:VARD_DADOS } else { "$env:LOCALAPPDATA\rdl-vard" }
$json = Get-Content "$dados\instalacao.json" -Raw | ConvertFrom-Json
$json.supervisor = $false
$json | ConvertTo-Json | Set-Content "$dados\instalacao.json"
```

### 2. Restaurar atalhos legados

```powershell
.\scripts\windows\tarefa-logon.ps1
```

Com `supervisor: false`, os atalhos voltam a apontar para `powershell.exe + vard-modo.ps1`.

### 3. Restaurar backup (se necessário)

```powershell
$dados = if ($env:VARD_DADOS) { $env:VARD_DADOS } else { "$env:LOCALAPPDATA\rdl-vard" }
if (Test-Path "$dados\instalacao.json.bak-0.7") {
  Copy-Item "$dados\instalacao.json.bak-0.7" "$dados\instalacao.json" -Force
}
```

### 4. Reiniciar a pilha legada

```powershell
.\scripts\windows\vard-modo.ps1 iniciar
```

## Comportamento dos adaptadores

| Componente | `supervisor: false` | `supervisor: true` |
|---|---|---|
| `vard-modo.ps1` | Executa verbos diretamente (legado) | Publica verbo na caixa IPC (`ciclo/pedidos/`) |
| `tarefa-logon.ps1` | Atalhos → `powershell.exe` | Atalhos → `vard.exe` |
| `bandeja.py` | Inicia normalmente | Não inicia (bandeja nativa assume) |
| Instância única | N/A | Plugin impede segunda abertura |

## Notas

- A migração **não** apaga configurações, modelos ou dados do usuário
- Atalhos alheios (não criados pelo Vard) são preservados
- O binário antigo pode ser removido após confirmação de funcionamento
- A ponte local e conectores continuam funcionando normalmente
