# Brief — Piece 1: recarregar recria thread do serviço

## Contexto
Hoje `parar()` encerra a thread do supervisor (`loop_servico` retorna) e `repetir()` apenas sinaliza `reiniciar`, mas como a thread já terminou, ninguém consome o sinal. O resultado é que após um `parar` + `repetir` o serviço nunca volta.

## Objetivo
Fazer com que `recarregar` (que chama `parar` + `repetir`) volte a subir o serviço de verdade. A solução deve garantir que, após `parar()`, uma chamada subsequente a `repetir()` (ou `iniciar`/`repetir_desistidos`) recrie a thread do supervisor se ela já terminou.

## Arquivos permitidos
- `src-tauri/src/servicos.rs` — único arquivo desta peça. NÃO toque em `ciclo.rs`, `bandeja.rs`, `src/**` nem `nucleo/vard/cerebro/**`.

## Requisitos
1. Após `parar(id)` seguido de `repetir(id)`, o serviço deve voltar ao estado `Subindo`/`Ok` (nova thread spawnada).
2. O registro global `SERVICOS` deve continuar válido: `foto(id)` deve retornar o novo PID após o reinício.
3. Se a thread ainda estiver viva quando `repetir` for chamado, o comportamento atual (sinal consumido no loop) deve ser preservado.
4. `encerrar_todos()` e `parar_e_aguardar()` devem continuar funcionando sem regressão.
5. Nenhum segredo, caminho absoluto pessoal ou dado real no código ou testes.

## Testes obrigatórios
Adicione pelo menos um teste em `servicos.rs::testes` que:
- Inicie um serviço falso (use `criar_filho_http_falso` existente),
- Chame `parar(id)` e espere a thread terminar,
- Chame `repetir(id)`,
- Verifique que o serviço volta a responder `/saude` com um **novo PID**.

Rode `cargo test --manifest-path src-tauri/Cargo.toml -p vard --lib servicos` e garanta que passa. Se o toolchain Linux não compilar o crate completo, documente o erro exato e quais testes rodaram.

## Prova
```bash
cd src-tauri && cargo test --lib servicos -- --nocapture
```

## Fora de escopo
- Mudanças em `ciclo.rs`, `bandeja.rs` ou qualquer arquivo fora de `servicos.rs`.
- Funcionalidade nova além de fazer `repetir` funcionar após `parar`.
- Integração com o frontend ou ponte Python.
